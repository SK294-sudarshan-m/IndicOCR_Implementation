== PHASE 0 FINDINGS (known unknowns) ==
1. Recognizer loads and runs on CPU under transformers 5.17.0 / torch 2.14.0+cpu. Noisy stderr (causal_conv1d fallback,
   tqdm bars) is suppressed in model.py.
2. dtype (same page, 4 transcribed blocks): bfloat16 recognizer 27.9 s, 3.49 GB peak; float32 16.9 s, 5.16 GB. DECISION: float32 on CPU,
   bfloat16 on CUDA. CUDA path is untested (no GPU).
3. DPI: CER 0.0000 at 100/150/200/300 dpi on clean 11 pt, clean 7 pt and a degraded 300-dpi scan (blur, noise, skew, JPEG q45).
   Time 26.7/26.3/31.0/43.9 s per page. Kept 200 dpi. The fixtures saturate, so this cannot show where real bad scans need more.
4. PDF text layers of Indic text are NOT always trustworthy: a MuPDF-generated Hindi PDF (Nirmala UI, shaped correctly) extracts with
   U+FFFD, detached matras ("व\nिशाल") and NBSP. quality.py catches this (replacement chars + orphan combining marks + stray
   Latin letters in Indic words), plus PUA, foreign-script ratio, word length, legacy font names. ASCII-mapped legacy fonts
   (Kruti Dev) are caught by font name only; never tested on a real file.
