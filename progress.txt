== PHASE 0 FINDINGS (known unknowns) ==
1. Does the recognizer load and run on CPU under transformers>=5.7 in a fresh venv?
   YES. transformers 5.17.0, torch 2.14.0+cpu. Layout + recognizer both load with device="cpu".
   Extra stderr noise: "causal_conv1d / flash-linear-attention not installed, falling back to reference PyTorch
   implementation" (correct but slower; those kernels are not installable on Windows CPU) and tqdm "Loading weights"
   bars. Both suppressed in model.py (TRANSFORMERS_VERBOSITY=error, HF_HUB_DISABLE_PROGRESS_BARS=1).
2. Seconds per page and peak RAM, dtype bfloat16 vs float32 (same page, 5 layout blocks / 4 transcribed, 4 threads):
        dtype      load(layout+rec)   layout   recognizer   page total   peak RSS
        bfloat16   5.0s + 5.6s        2.9s     27.9s        30.9s        3.49 GB
        float32    3.5s + 4.8s        3.0s     16.9s        19.9s        5.16 GB
   Same output lengths in both. DECISION: float32 on CPU (1.65x faster recognizer), bfloat16 on CUDA.
   Both fit easily in 15.7 GB. Single run each; treat as +/-10%.
3. Render DPI (clean synthetic page, mixed English/Hindi, 11 pt, fp32):
        dpi   px          layout+ocr      CER
        150   1240x1755   25.9s           0.0000
        200   1653x2339   31.9s           0.0000
        300   2480x3509   44.5s           0.0000
   No accuracy difference on clean 11 pt text; time grows with dpi. (7 pt run: see below.)
4. Are PDF text layers of Indic-script PDFs trustworthy?
   NOT NECESSARILY. A synthetic Hindi PDF made with MuPDF's HTML story engine and Nirmala UI (shaped correctly on
   screen) extracts as: NBSP (U+00A0) instead of spaces; "हœ" for "हैं"; "द\nिʟी" for "दिल्ली"; "व\nिशाल" for
   "विशाल" (spurious line break before a matra, orphan matras at line start, Latin letters inside Devanagari words).
   A script-block check alone would pass this text. So quality.py also counts orphan combining marks and
   mixed-script words. Limits: one generator only; I have no real-world legacy-font (Kruti Dev, ASCII-mapped) PDF,
   so that case is covered by a font-name list only, not measured.
